# 2026-11-15 — Path settings per system (issue #63)

One synced `data.json` broke the export on the other OS: a Windows `pandocPath` fails on Linux and back, and the `extraPath` separator differs.

## Changes

- New `src/app/domain/platform-paths.ts`: `PlatformPaths` (`windows` / `linux` / `macos` × `pandocPath`, `pdfEnginePath`, `extraPath`, `defaultOutputDir`), `normalizePlatformPaths`, `detectHostPlatform`, `resolvePlatformSettings`.
- `PluginSettings.platformPaths` (all empty by default). `loadSettings` normalizes it (partial or hand-edited object never leaves a field undefined).
- `plugin.hostPlatform` (from Obsidian `Platform`) + `plugin.effectiveSettings()`. Preflight probe and every command read paths through it.
- Settings tab: rows for this device's system first (`platform.<system>.<field>` control keys), the old rows renamed "(shared)", new sub-page "Paths on other systems".
- Business rule 13. Docs: `docs/configuration.md`, README troubleshooting, `documentation/Configuration.md`.

## Decisions

- Old single values stay as the shared fallback: no migration, existing vaults unchanged.
- macOS included: same mechanism, and it already needs absolute paths (Homebrew, MacTeX).
- Stored in `data.json` (synced), not per-device local storage: one device can set the paths of the others.
